# HolyCrab — Game Design v2.8

## 1. 핵심 컨셉

HolyCrab은 라먀니가 엄마의 간장게장 레시피를 **10일 동안 생활 동선을 추적해 조금씩 빼내는 스텔스 코미디**다.

핵심은 세 가지다.

1. 같은 장소를 여러 차례 다시 방문한다.
2. 조사 가능한 기록 중에는 가짜 레시피와 아무 의미 없는 생활 메모가 섞여 있다.
3. 후반으로 갈수록 엄마의 AI가 강해지고 언니까지 추가되지만, 플레이어도 제한적인 일회용 아이템을 얻는다.

## 2. 캠페인 구조

총 10일.

- **집 3회**
  - Day 1 고정
  - Day 2~9 사이 중간 재방문 1회
  - Day 10 최종 작전 고정
- **시장 + 반찬가게 7회**
  - 4회 / 3회로 배분
  - 어느 장소가 4회인지는 캠페인 시드에 따라 달라짐

중간 8일은 가능한 한 같은 장소가 연속되지 않게 배치한다.

집은 스토리의 기준점이고, 시장/반찬가게는 반복 조사 공간이다. 따라서 외부 장소는 방문할 때마다 새로운 핵심 기록을 제공하도록 최대 4개의 방문 템플릿을 가진다.

각 방문 템플릿은 정보만 바꾸지 않는다. `layoutKey`와 `layoutName`을 가지며, 방문 차수별 임시 충돌물·활성 숨기 포인트·환경 유인 장치를 함께 바꾼다. 추가된 충돌물은 기존 NPC 경로탐색 검증을 반드시 통과해야 한다.

## 3. 정보 구조

핵심 기록은 진행 조건에 포함된다.

예:

- 간장 : 물 기본 비율
- 꽃게 선택 기준
- 향채 구성
- 매실청 사용
- 간장물 완전 냉각
- 1차 숙성 24시간
- 게 분리 후 간장물 재가열
- 2차 숙성

### 혼선 기록

각 스테이지에는 핵심 기록 외에 혼선 기록을 섞는다.

**가짜 레시피**
- 실패한 실험안
- 오래된 레시피
- 광고/판촉 문구
- 다른 음식의 비율이나 작업표
- 틀린 숙성 시간

**의미 없는 메모**
- 택배 목록
- 주차권
- 직원 교대표
- 야식 메모
- 시장 행사 안내
- 숫자만 적힌 박스 표기

진짜와 가짜는 같은 조사 마커를 사용할 수 있지만, 내용 자체는 추론이 필요 없을 만큼 명백하게 틀린 방향으로 작성한다.

예:
- 민트초코 아이스크림을 간장물에 넣기
- 담뱃재를 한 꼬집 넣기
- 치약을 생강 대신 사용하기
- 초콜릿 시럽이나 마요네즈로 숙성하기
- 라면수프를 세 봉지 넣기

가짜 레시피를 다른 기록과 대조해서 판별하거나 정답을 확정하는 별도 시스템은 사용하지 않는다. 가짜/생활 메모는 단순 탐색 방해 요소이며 진행 조건에 포함되지 않는다.

혼선 밀도:
- Day 1~4: 2개
- Day 5~10: 3개

## 4. 엄마 AI

상태:
- Patrol
- Investigate
- Search
- Chase
- Return

행동:
- 시야에 들어오면 의심 증가
- 플레이어 이동 속도가 빠르면 더 빨리 확정 탐지
- 마지막 목격 위치 기억
- 소리가 난 위치 기억
- 놓치면 마지막 위치 주변 다점 수색
- 플레이어 이동 벡터를 이용한 짧은 예측 추적
- 벽/가구 뒤 소리 감쇠
- 날짜와 누적 발각 횟수에 따른 경계도 상승

## 5. 언니

Day 5부터 등장.

- 엄마와 별도 순찰 경로
- 독립적인 기억/시야/청각/의심
- Day 5에는 비교적 완만한 성능으로 시작하고 Day 9까지 단계적으로 강화
- 최종일에는 별도 고난도 수치 사용
- 교차 동선 사용
- 환경 유인은 가까운 추적자가 더 크게 반응해 둘의 동선을 분리할 수 있음

## 6. 플레이어 아이템

아이템은 **매일 월드에 정확히 1개 배치**하고 플레이어가 직접 찾아서 줍는다.

배치 규칙:
- 10일 캠페인 전체 기준 포장끈 5개 / 담배 5개
- 날짜별 종류는 캠페인 시드로 섞음
- 같은 종류가 3일 연속 나오지 않도록 제한
- 포장끈과 담배는 각각 최대 2개 보유
- 보유 한도가 가득 차면 아이템은 맵에 남아 있고, 사용 후 다시 획득 가능
- 그날 줍지 못한 아이템은 다음 날 자동 지급되지 않음
- 이미 주운 수량은 다음 날로 이월

### 포장끈

- 단축키: 1
- 사거리: 약 76px
- 가장 가까운 엄마 또는 언니 한 명 대상
- 8초간 이동과 탐지 정지
- 해제 후 경계도 상승
- 해제 위치 주변부터 수색 재개
- 1회 사용 시 1개 소모

의도: 추격을 완전히 삭제하는 무기가 아니라 좁은 통로나 최종 탈출 때 짧은 시간 창을 만드는 비상 수단.

### 담배

- 단축키: 2
- 지속: 7초
- 이동 속도: +45%
- 사용 즉시 큰 소음 1회
- 지속 중 추가 기침 소음 1회
- 1회 사용 시 1개 소모

의도: 도주 능력을 크게 올리는 대신 감시자에게 위치를 노출할 가능성을 만드는 고위험 이동 아이템.

### 조사·숨기·환경 유인

- 핵심 단서와 혼선 기록은 동일한 마커를 사용한다.
- 메모 조사 시 약 0.65초 동안 이동이 잠기므로 위험 지역에서 무작정 연타하는 방식은 불리하다.
- 아이템 줍기와 유인 장치 조작도 짧은 행동 고정 시간이 있다.
- 플레이어가 숨는 동안 일반 시야 판정에서는 제외되지만, Investigate/Search/Chase 상태의 추적자가 숨은 지점 54px 이내까지 접근하면 발각된다.
- 숨은 상태에서 수색자가 110px 이내로 접근하면 화면에 경고한다.
- 환경 유인은 장치당 해당 Day 1회만 유효하며, 사용 상태는 저장/이어하기에도 유지한다.
- 두 추적자가 있을 때는 유인 지점에 가까운 추적자가 전체 강도로 반응하고 다른 추적자는 약화된 반경으로 반응한다.

## 7. 장소별 반복 의미

### 집 — 총 3회
1. 시작: 장보기 동선 발견
2. 중간: 집으로 들어온 재료와 흔적 확인
3. 최종: 원본 레시피 확보

### 전통시장 — 3~4회
- 꽃게/간장 선택
- 향채/매실청
- 단골 구매 패턴 교차 검증
- 최종 구매 흔적 재확인

### 반찬가게 — 3~4회
- 냉각/단맛
- 숙성/재가열
- 폐기안과 현재 작업법 비교
- 2차 숙성 반복 공정 확인

## 8. 최종 작전

Day 10 집은 일반 집 방문과 다른 `home-finale-lockdown` 레이아웃을 사용한다.

1. 최종 핵심 기록 확보
2. 황당한 가짜 레시피와 생활 메모는 무시
3. 평소보다 줄어든 숨기/유인 자원으로 원본 위치 접근
4. 숨겨 둔 원본 레시피 직접 획득
5. 원본을 꺼내는 소음으로 엄마 + 언니의 조사 상태 활성화
6. 필요하면 포장끈/담배를 사용해 현관까지 최종 탈출

원본을 확보한 상태에서 저장 후 재접속하더라도 안전 재진입 지점으로 이동하지 않는다. 원본 위치에서 다시 시작하고 최종 소음 반응을 재생해 클라이맥스를 건너뛰는 재접속 우회를 막는다.

퀴즈는 사용하지 않는다.

## 11. VN Scene 시스템

기존 HOLYCRAB 로고 중심 인트로는 사용하지 않는다. 대신 하나의 미연시 스타일 UI를 다음 이벤트에 공통으로 재사용한다.

- 프롤로그/튜토리얼: 라먀니가 게임 목적, 이동, 은신, 조사, 아이템 사용법을 대사로 설명
- Day 시작: 오늘 장소와 목표를 안내
- 발각: 엄마 또는 언니의 초상과 대사 → 라먀니 반응 → 동일 Day 재개
- Day 결산: 핵심 단서 수, 불필요 메모 조사 수, 일일 아이템 획득 여부, 당일 발각 횟수 표시
- 엔딩: 원본 레시피 확보 후 가족 대화와 최종 결과 연결

초상은 `assets/vn/ramyani.png`, `mom.png`, `sister.png`의 투명 PNG를 사용한다. 장면 데이터는 `src/story.js`, 화면 재생은 `src/game.js`가 담당해 대사 데이터와 게임 로직을 분리한다.


## 12. 동선 가독성

문·통로는 배경이나 벽과 같은 명도로 묻히지 않도록 별도 시각 레이어를 사용한다.

- 벽은 바닥보다 어둡게 유지하되 얇은 밝은 외곽선을 둔다.
- 실제 충돌벽 사이의 통로는 따뜻한 반투명 바닥색과 외곽선으로 표시한다.
- 집의 방↔거실, 거실↔부엌 통로와 반찬가게의 판매대↔뒷주방 통로는 명시적 passage 데이터로 유지한다.
- 출구는 진행 불가 상태에서도 완전히 회색으로 죽이지 않고 따뜻한 색으로 식별 가능하게 한다.
- 출구가 활성화되면 녹색으로 바뀌며, 화면 가장자리 방향에 맞춰 가로/세로로 그린다.


## 13. 일시정지와 세션 복구

- 플레이 중 `Esc`로 일시정지/재개한다.
- 탭 또는 창이 비활성화되면 자동으로 일시정지한다.
- 진행 중 약 8초 주기 및 핵심 진행 이벤트에서 자동 저장한다.
- 저장 데이터는 버전 검증을 거쳐 읽으며, 손상되거나 현재 캠페인 구조와 맞지 않는 저장은 무시한다.
- 저장 항목은 캠페인 시드, 현재 Day, 확보 기록, 획득 아이템, 사용한 환경 유인 장치, 남은 인벤토리, 원본 확보 여부, 발각 횟수, 경과 시간이다.
- 재개 시 추적자는 초기 배치로 돌아가고 라먀니는 현재 Day의 안전한 재진입 지점으로 이동하되 저장된 진행 정보는 유지한다.
- 단, 최종 원본을 이미 확보한 저장은 원본 위치의 탈출 구간에서 다시 시작하고 최종 추적자 반응도 재생한다.
- 캠페인 완주 시 이어하기 저장은 삭제한다.

## 14. 시야 표시와 판정 일치

추적자의 시야 표시는 단순 부채꼴을 사용하지 않는다. 실제 LOS 판정에서 사용하는 벽과 가구를 동일한 차폐물로 보고 여러 개의 레이를 발사해 가장 가까운 차폐 지점에서 시야 폴리곤을 자른다.

의도:
- 그래픽상 보이는데 실제로는 감지하지 않는 오해를 줄인다.
- 벽을 관통하는 시야 콘을 제거한다.
- 엄마와 언니 모두 동일한 시야 차폐 규칙을 사용한다.

## 15. 런타임 회귀 검증

정적 문자열 검사만으로 플레이 가능성을 판단하지 않는다.

CI에서 실제 `src/game.js`를 headless DOM/Canvas/Audio 스텁 환경에 로드하고 다음 최소 흐름을 실행한다.

1. 중립 시작 화면 표시
2. 새 게임 시작
3. 프롤로그와 Day 1 VN 진행
4. 실제 플레이 상태 진입
5. `Esc` 일시정지와 재개
6. 자동 저장 생성
7. 새 런타임 인스턴스에서 이어하기 노출
8. 저장된 Day 복구 후 다시 일시정지 가능 여부 확인

이 스모크 테스트는 브라우저 렌더링 픽셀 검증을 대체하지 않지만, DOM ID 누락·모듈 로딩 실패·초기화 예외·주요 상태 전이 단절을 CI에서 잡는 역할을 한다.


## 16. 반복 방문 물리 변형

반복 장소는 기본 건물 구조와 주요 랜드마크를 유지해 장소 학습의 보상을 남기되, 매 방문의 최적 동선이 완전히 같아지지 않도록 작은 물리 변형을 적용한다.

원칙:
- 핵심 벽과 방 구조는 유지한다.
- 임시 가구/상자/카트처럼 현실적으로 이동 가능한 물체만 추가 충돌물로 사용한다.
- 필수 단서·아이템·출구를 새 임시 장애물로 직접 막지 않는다.
- 숨기 포인트와 환경 유인 장치는 방문별 일부만 활성화한다.
- 같은 장소의 반복 방문은 서로 다른 layoutKey를 가져야 한다.
- 캠페인 테스트는 각 반복 방문의 물리/자원 시그니처가 실제로 다른지 검증한다.
- 최종일은 별도 lockdown 레이아웃과 원본 획득 후 탈출 트리거를 사용한다.


## 17. 상태 피드백과 연출

연출은 게임 판정과 별도의 허구 상태를 만들지 않는다. 모든 경고와 효과는 현재 추적자 AI 상태 또는 실제 의심도에서 직접 계산한다.

### 위험도

- 엄마/언니 중 가장 높은 의심도를 플레이필드 가장자리 비네트 강도로 사용한다.
- 의심도 55% 이상은 상단 추적자 카드와 가장자리 효과를 경고 상태로 표시한다.
- 의심도 72%를 처음 넘으면 짧은 경고음과 `발각 임박` 이벤트를 1회 표시한다.
- 의심도가 45% 이하로 충분히 떨어진 뒤에만 같은 임계 경고가 다시 발동할 수 있다.

### 추격

- AI가 실제 `CHASE` 상태에 처음 진입한 추적자만 추격 시작 이벤트를 발생시킨다.
- 상태가 유지되는 매 프레임마다 소리나 배너를 반복하지 않는다.
- 모든 추적자가 `CHASE`에서 빠져나오면 `시야 이탈` 피드백을 1회 표시한다.
- 발각 처리 시 추격 피드백 상태를 먼저 초기화해 발각 VN 뒤에 잘못된 `시야 이탈` 이벤트가 나오지 않도록 한다.

### 획득·전환

- 핵심 단서는 현재 Day의 확보 개수와 함께 표시한다.
- 혼선 기록은 핵심 단서와 다른 낮은 우선순위 피드백을 사용한다.
- 아이템은 현재 보유량/최대 보유량을 이벤트 배너에 표시한다.
- Day 시작은 장소와 `layoutName`을 표시한다.
- 최종 원본 획득은 일반 성공음이 아닌 별도 경고음과 탈출 이벤트를 사용한다.
- 결과 화면은 성공 패널과 등급에 짧은 진입 애니메이션을 적용한다.

### 레이어 우선순위

- 영구 HUD: 플레이필드 바깥 상·하단 바
- 위험 비네트: 플레이필드 안쪽, 기록창보다 아래
- 상태 이벤트 배너: 플레이필드 상단
- 설명 토스트: 이벤트 배너 아래
- VN/일시정지/결과: 위 레이어 전체를 덮는 모달

사용자가 OS에서 `prefers-reduced-motion: reduce`를 선택한 경우 CSS 애니메이션과 전환 시간을 사실상 제거한다.


## 18. 성능·장시간 안정성

### 렌더링

- 스테이지의 바닥, 구역명, 격자, 벽, 통로, 가구는 정적 캔버스 레이어로 한 번 렌더링한다.
- 플레이 프레임에서는 정적 레이어를 `drawImage`로 복사하고 플레이어, 추적자, 시야, 상호작용 오브젝트, 소음만 동적으로 그린다.
- 스테이지 교체 시 이전 정적 캔버스의 폭/높이를 0으로 만들어 backing store 해제를 유도한다.
- 시야 판정은 매 프레임 수행하지만 시야 폴리곤 렌더용 raycast는 32 ray, 최대 50ms 캐시를 사용한다. 위치 3px 이상, 각도 약 0.035rad 이상, 시야 거리/FOV 변화가 있으면 캐시를 즉시 갱신한다.

### 게임 루프

- `requestAnimationFrame`은 실제 `playing` 상태에서 지속 실행한다.
- 시작 화면, VN, 일시정지, 결과 화면에서는 동적 월드가 변하지 않으므로 루프를 중지한다.
- 비플레이 상태에서 월드가 바뀐 경우 `renderDirty`로 필요한 한 프레임만 다시 그린다.
- VN 종료, 이어하기, 일시정지 해제, BFCache `pageshow`에서 필요할 때만 루프를 다시 깨운다.
- 프레임 delta는 기존과 같이 최대 35ms로 제한하며 `pageshow`에서 기준 시간을 재설정한다.

### AI / 경로

- 추격 목표는 움직이므로 약 0.24초 단위 재탐색을 허용한다.
- 순찰·조사·수색·복귀의 고정 목표는 기존 0.62초 주기 재탐색을 제거하고 긴 safety interval을 사용한다.
- 목표가 34px 이상 이동하거나 경로가 끝나거나 실제 이동이 정지된 경우에는 즉시 재탐색한다.
- 이 변경은 실제 시야/탐지 판정 주기를 낮추지 않는다.

### UI / 임시 상태

- 미션 HUD는 단서 획득, 원본 확보, 발각, 스테이지 전환 같은 상태 이벤트에서만 갱신한다.
- 프롬프트와 의심도 HUD는 50ms 간격으로 갱신하며, 값이 달라진 DOM 속성만 기록한다.
- 담배 부스트 시간 표시는 0.1초 단위 문자열이 바뀔 때만 갱신한다.
- 소음 링은 24개 상한과 제자리 제거를 사용한다.
- 추격자 상태 비교는 매 프레임 `Set`을 만들지 않고 bit mask를 사용한다.
- WebAudio 임시 노드는 `onended`에서 disconnect한다.

### 회귀 검증

Headless 런타임 하네스는 제어 가능한 `requestAnimationFrame`과 가짜 Canvas를 사용해 다음을 확인한다.

1. 시작 화면에서 지속 프레임이 예약되지 않음
2. 스테이지 로드시 정적 캔버스가 한 번 생성됨
3. VN에서 필요한 월드 한 프레임 렌더 후 루프 정지
4. 실제 플레이 진입 시 루프 재시작
5. 일시정지 후 예약 프레임 소멸
6. `pageshow`에서 필요한 한 프레임만 복구 후 다시 정지
7. 재개 시 플레이 루프 재시작


## 19. 캠페인 종단간 검증

### 플레이어 접근성

NPC 경로 연결성만으로 스테이지 유효성을 판단하지 않는다. 플레이어 기준으로 다음 오브젝트에 실제 상호작용 가능한 위치가 존재해야 한다.

- 모든 핵심 단서
- 매일 배치되는 아이템
- 최종일 원본 레시피 위치
- 각 Day 출구

검증 조건:
- 플레이어 반경 16px
- 벽 + 가구 충돌 반영
- 상호작용 최대 거리 72px
- 실제 게임과 동일하게 상호작용 LOS는 벽으로 차단
- 일반 spawn과 retry spawn 모두에서 동일 필수 오브젝트에 접근 가능

비용을 줄이기 위해 오브젝트마다 A*를 반복하지 않는다. 각 시작점에서 한 번 flood-fill로 플레이어가 도달 가능한 walkable component를 계산한 뒤 모든 필수 오브젝트의 상호작용 접근점을 검사한다.

### 런타임 보호

`loadStage()`는 다음 순서로 스테이지를 검증한다.

1. 구조/ID/배치 기본 검증
2. 엄마·언니 순찰 경로 연결성 검증
3. 플레이어 필수 진행 오브젝트 접근성 검증

세 단계 중 하나라도 실패하면 해당 스테이지를 실행하지 않고 명시적 오류를 발생시킨다.

### 실제 10일 자동 완주

Headless 런타임 테스트는 고정 시드 캠페인에서 실제 `game.js` 상태 머신을 사용해 다음 흐름을 실행한다.

1. 저장된 Day 1 캠페인 이어하기
2. 매일 실제 E 상호작용으로 아이템 획득
3. 획득 아이템 실제 사용
4. 모든 핵심 단서 실제 수집
5. Day 2와 Day 7에서 강제 발각 후 진행 보존 확인
6. Day 5 도중 저장 후 새로운 런타임 인스턴스로 이어하기
7. 저장된 단서, 아이템, 인벤토리, 발각 횟수 비교
8. 각 Day 출구를 실제로 사용해 다음 Day로 전환
9. Day 10 최종 단서 → 원본 레시피 → 최종 탈출 실행
10. 엔딩 VN 종료 후 결과 화면 도달 및 저장 삭제 확인

테스트가 오브젝트까지 순간이동하는 기능은 이동 경로를 우회하기 위한 것이 아니라, 별도 접근성 검증에서 해당 위치까지의 합법적 경로가 이미 확인된 뒤 실제 상호작용/상태 전이만 재현하기 위한 테스트 전용 수단이다. 테스트 훅은 `window.__HOLYCRAB_TEST__ === true`일 때만 생성한다.
